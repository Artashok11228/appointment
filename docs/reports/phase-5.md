## چه کاری انجام شد

یک تست همزمانی با گروه `mysql` اضافه شد که دو فرایند جدا برای یک اسلات رزرو می‌زنند.
روی غیر مای‌اس‌کیوال خودش را رد می‌کند.
بخش `Testing` در README نحوه اجرای این گروه را توضیح می‌دهد.

## فایل‌های تغییر کرده

- `tests/Feature/ConcurrentBookingTest.php`: دو فرایند موازی و انتظار یک برنده
- `README.md`: بخش `Testing` برای SQLite و گروه `mysql`
- اسکریپت موقت `storage/framework/testing/book-once.php` هنگام تست ساخته می‌شود

## چطور کار می‌کند

اگر درایور پایگاه داده مای‌اس‌کیوال نباشد، تست با `markTestSkipped` رد می‌شود.
با `migrate:fresh` یک دیتابیس واقعی آماده می‌شود، نه تراکنش `RefreshDatabase`.
دو مشتری و یک سرویس ساخته می‌شوند. دو فرایند PHP جدا همان اسلات را می‌خواهند.
هر فرایند `CreateAppointment` را صدا می‌زند. یکی موفق می‌شود و دیگری `AppointmentUnavailable` می‌گیرد.
خروجی‌ها باید `[0, 2]` باشند و در جدول فقط یک نوبت بماند.

## یک تصمیم طراحی مهم

به‌جای دو درخواست در یک فرایند، دو فرایند جدا ساختم.
قفل ردیف مای‌اس‌کیوال بین دو اتصال جدا دیده می‌شود. در یک اتصال و داخل یک تست ترتیبی، قفل واقعی سنجیده نمی‌شود.

## سؤال احتمالی مصاحبه

چرا این تست روی SQLite اجرا نمی‌شود؟
چون `lockForUpdate` روی SQLite حافظه مثل اینودب قفل نمی‌گیرد. گروه `mysql` همان رفتار واقعی را می‌سنجد.

## چطور تست کنم

```bash
php artisan test
./vendor/bin/pint
DB_CONNECTION=mysql DB_DATABASE=appointment_booking_test php artisan test --group=mysql
```

سوئیت پیش‌فرض: ۷۷ پاس، ۱ ردشده. Pint پاس. مای‌اس‌کیوال در این محیط نبود، پس گروه `mysql` اینجا اجرا نشد.
